# 최종 검증 기록

확인일: 2026-11-13. 환경: macOS, Java 21, MySQL 8.4, Chrome.

## 자동 검사

| 검사 | 결과 |
| --- | --- |
| Gradle 전체 build | 성공 |
| Java 테스트 | 26개 통과, 실패·건너뜀 없음 |
| Node 프런트 테스트 | 13개 통과 |
| 변경 파일 공백 오류 검사 | `git diff --check` 통과 |
| 발표 데이터 생성 | 첫 실행·재실행 성공, 같은 일기장 사용 |

Java 검사는 DB 대역을 사용하는 회원가입·인증·세션·일기·삭제 권한 검사다.
트랜잭션 롤백과 실제 SQL은 아래 별도 MySQL 검증으로 확인했다.

```bash
./backend/gradlew -p backend build
node --test frontend/tests/auth.test.mjs frontend/tests/diary.test.mjs
```

Windows PowerShell에서는 첫 명령을 `.\backend\gradlew.bat -p backend build`로 바꾼다.

## 실제 MySQL·Chrome 통합 확인

기존 개발 데이터와 분리된 임시 DB에서 확인했다. 브랜치의 실제 HTML·JS·CSS를 Chrome에 제공하고
API 주소만 별도 테스트 서버의 18080 포트로 연결했다. 아래 흐름을 localhost와 127.0.0.1 각각 확인했다.
테스트 브라우저의 로컬 네트워크 권한은 해당 임시 컨텍스트에만 부여했다.

- 로그인 → 그룹 상세 → 빈 일기 목록 → 작성 → 상세 이동.
- 작성된 한글·줄바꿈·태그 모양 문자열이 데이터로 보존되고 HTML로 실행되지 않음.
- 일기 5개 API 모두 미로그인 401, 비멤버 404.
- 방장도 타인의 개별 일기는 수정·삭제할 수 없음. 관련 버튼 숨김과 서버 403 모두 확인.
- 다른 일기장의 ID를 붙인 조회·수정·삭제는 404.
- 빈 입력·길이 초과·잘못된 ID·깨진 JSON은 400, 잘못된 데이터가 저장되지 않음.
- 수정 실패 후 입력 유지·재시도, 새로고침 후 내용 유지, 수정 시각 갱신.
- 개별 일기 삭제 취소·확인.
- 작성자는 클라이언트 전달값 대신 서버 세션에서 결정.
- 방 나가기 후 일기 접근을 차단하고 기존 글은 남은 멤버에게 유지.
- 미로그인 보호 화면 접근은 로그인 화면으로 이동.
- 일기장 삭제는 미로그인 401·비멤버 404·일반 멤버 403, 방장만 실행 가능.
- **임시 DB에 삭제 실패 트리거를 설정해 오류를 유발했을 때, 일기·멤버·일기장이 모두 보존됨.**
- 일기장 삭제 취소·네트워크 실패 후 재시도. 성공하면 해당 일기·멤버만 삭제하고 다른 일기장과 사용자 계정은 유지.
- 하위 화면에서 로그아웃 성공, 이후 세션 조회 401과 보호 화면 이동 확인.
- 390px 모바일 화면의 가로 넘침과 메뉴·삭제 안내 확인.

검증용으로 만든 트리거는 검사 후 제거했다. 운영용 데이터에 오류 유발 트리거를 설치하지 않는다.
실제 Windows PC에서의 설치·실행은 이 macOS 검증에 포함되지 않았다. 팀원은 발표 전에 아래 흐름을 본인 PC에서 확인한다.
