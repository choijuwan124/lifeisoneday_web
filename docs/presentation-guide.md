# 마지막 주 발표·시연 안내

## 발표 전에 준비

- Java·MySQL·프런트 서버를 실행하고 로그인 화면이 열리는지 확인한다.
- `node scripts/seed-demo.mjs`로 계정 2개와 백업용 일기장·일기를 준비한다.
- `.local/demo-credentials.json`에서 계정 정보를 본다. 비밀번호 파일을 화면 공유하지 않는다.
- 일반 창은 방장 계정, 시크릿 창 또는 별도 브라우저 프로필은 친구 계정으로 로그인한다.
- 두 창 모두 같은 호스트 주소를 사용한다. 단순히 같은 브라우저에서 탭만 나누면 로그인 쿠키가 공유된다.
- 시연은 새로 만든 발표 전용 일기장에서 진행한다. 미리 준비된 일기장은 예비 자료로 남긴다.
- GitHub의 PR 목록과 커밋 그래프를 별도 탭에 열어둔다.
- 빌드·테스트 결과와 실제 실행 화면을 확인한다. Windows 실물 환경에서도 각자 발표 전에 한 번 실행한다.

## 실제 시연 순서

1. 첫 화면에서 회원가입 화면과 필수값 검사를 보여준다. 필요하면 별도 새 계정으로 가입한다.
2. 준비된 방장 계정으로 로그인한다. 상단 닉네임과 내 일기장 목록을 보여준다.
3. 새 일기장 `발표 시연 일기장`을 만든다.
4. 초대 전 친구 창에서는 이 일기장이 목록에 없다는 것을 보여준다.
5. 방장 창의 멤버 관리에서 준비된 친구 아이디로 초대한다. 같은 아이디를 다시 넣어 중복 초대 차단도 보여준다.
6. 친구 창에서 목록을 새로고침해 참여한 일기장에 들어간다.
7. 친구가 일기를 작성한다. 방장 창에서 읽되 수정·삭제 버튼이 없다는 점을 보여준다.
8. 친구 창에서 본인 글을 수정한다. 새로고침해 수정 내용이 보존되는 것을 보여준다.
9. 별도 연습 글을 하나 더 만들어 삭제를 취소한 뒤 실제 삭제한다.
10. 친구가 방을 나간다. 친구 목록에서는 사라지고 방장에게는 친구의 첫 글이 남는 것을 보여준다.
11. 방장만 일기장 전체를 삭제할 수 있음을 설명하고, 방금 만든 시연 일기장을 확인창 후 삭제한다.
12. 로그아웃한 뒤 일기장 페이지에 접근하면 로그인 화면으로 이동하는 것을 보여준다.

시연 중 오류가 나면 비밀번호나 로컬 설정 파일 대신 화면의 오류 메시지와 기능 흐름을 설명한다.
서버를 다시 켜야 한다면 재로그인한다. 시간이 부족하면 미리 만든 백업 일기장으로 조회·수정을 시연한다.

## Git 수업에서 강조할 부분

- 각자 로컬 폴더에서 clone하고, 공유 `main`에서 분리한 기능 브랜치에서 작업했다.
- **파일 하나 구현 → 검사 → 해당 파일만 commit → push → 다음 파일** 순서로 기록했다.
- 다른 담당의 기능을 사용하기 전에 병합된 최신 main을 받았다.
- PR로 실제 코드를 검토하고, merge commit을 사용해 개별 커밋을 유지했다.
- AI 생성 코드도 그대로 합치지 않고 컴파일·권한·DB·브라우저를 확인했다.

실제 수정 사례:

1. 일기 기능 PR #16 검토에서 `DiaryRepository.java`의 마지막 중괄호 누락으로 빌드가 실패했다.
2. 수정 커밋을 따로 남기고 테스트 후 병합했다.
3. 마지막 통합에서는 일기장 삭제와 로그인 상태 확인을 보완했다.
4. 실제 MySQL에서 삭제 도중 오류를 발생시켜 전체 삭제가 롤백되는지도 확인했다.

```bash
git log --graph --oneline --decorate --all -40
git log --oneline -- frontend/diary/diary.js
git show --stat 76b8052
```

## 설명할 수 있어야 하는 질문

| 질문 | 답변 핵심 |
| --- | --- |
| 왜 브랜치를 사용했나? | 공용 main과 작업을 분리하고 PR에서 검토하기 위해 |
| 로그인은 어떻게 유지하나? | 서버 세션과 JSESSIONID 쿠키. 로그인 성공 때 세션 ID 교체 |
| 남의 글 수정은 어떻게 막나? | 버튼 표시뿐 아니라 서버가 현재 멤버·작성자를 검사 |
| 방을 나가면 글도 지워지나? | 멤버 참여 정보만 삭제하고 기존 글은 남김 |
| 일기장 삭제 중 오류가 나면? | 일기·일기장 삭제가 하나의 트랜잭션이므로 롤백 |
| 비밀번호는 어떻게 저장하나? | 원문 대신 salt를 포함한 PBKDF2 해시 |
| 테스트가 통과하면 충분한가? | 대역 테스트와 실제 MySQL·브라우저 검증을 구분해서 확인 |

현재는 로컬 웹 과제 범위다. 배포, 이메일 초대 수락, 방장 위임 등은 향후 기능으로 설명한다.
발표 자체와 발표 시간에 맞춘 리허설은 팀이 최종 진행한다.
